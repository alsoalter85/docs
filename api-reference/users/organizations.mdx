---
title: "Get user organizations"
description: "Retrieve the list of Scalestack organizations a given user belongs to, including each organization's name and the user's assigned role within it."
---

A single Scalestack user account can belong to multiple organizations. Each organization membership carries a role that determines what actions the user can perform within that organization. Use this endpoint to retrieve the organizations associated with a given user ID, along with their role in each one.

## Get user organizations

Returns all organizations that a specified user belongs to.

```
GET https://backend.scalestack.ai/v2/users/{user_id}/organizations
```

### Path parameters

<ParamField path="user_id" type="string" required>
  The ID of the user whose organizations you want to retrieve. To get the authenticated user's own organizations, use the user ID returned by `GET /users/`.
</ParamField>

### Example request

```bash
curl https://backend.scalestack.ai/v2/users/usr_1a2b3c/organizations \
  -H "Authorization: Bearer <api_key>"
```

### Response

Returns a `UserOrganizationsResponse` object.

<ResponseField name="organizations" type="array">
  An array of `UserOrganizationItem` objects representing each organization the user belongs to.

  <Expandable title="UserOrganizationItem properties">
    <ResponseField name="id" type="string">
      The unique identifier for the organization.
    </ResponseField>
    <ResponseField name="name" type="string">
      The display name of the organization.
    </ResponseField>
    <ResponseField name="role" type="string">
      The user's role within this organization. Roles control what actions the user can perform — see [Roles](#roles) below.
    </ResponseField>
    <ResponseField name="created_at" type="string">
      ISO 8601 timestamp of when this organization was created.
    </ResponseField>
  </Expandable>
</ResponseField>

### Example response

```json
{
  "organizations": [
    {
      "id": "org_xyz789",
      "name": "Acme Corp",
      "role": "admin",
      "created_at": "2023-06-01T10:00:00Z"
    },
    {
      "id": "org_abc456",
      "name": "Acme Labs",
      "role": "member",
      "created_at": "2024-01-15T14:30:00Z"
    }
  ]
}
```

---

## Roles

Each organization membership includes a `role` value that determines the user's permissions within that organization.

| Role | Description |
|---|---|
| `owner` | Full control over the organization, including billing, member management, and all settings. |
| `admin` | Can manage members, workflows, and integrations. Cannot change billing or transfer ownership. |
| `member` | Can create and run workflows and view organization resources. Cannot manage members or settings. |
| `viewer` | Read-only access to organization resources. Cannot create or modify workflows. |

<Note>
  Role definitions and the specific permissions they grant may evolve as Scalestack adds new features. Contact your organization owner if you need elevated access.
</Note>
