---
title: "Query usage and credit consumption metrics"
description: "Aggregate Scalestack usage by workflow, module, user, or date. Filter by IDs or date ranges to understand credit consumption and run activity."
---

The usage query endpoint lets you pull aggregated metrics about how your organization is consuming Scalestack credits. You can filter by specific workflows, modules, or users, group results by different dimensions, and scope the data to a time period or custom date range. This is useful for building internal dashboards, tracking per-team spend, or auditing usage against your credit plan.

## Query usage metrics

Returns aggregated usage data for your organization based on the filters and grouping you specify.

```
POST https://backend.scalestack.ai/v2/usage/query
```

### Body parameters

<ParamField body="filters" type="object">
  An optional set of filters to limit which usage records are included. If omitted, all usage for your organization is included.

  <Expandable title="UsageFilter properties">
    <ParamField body="workflow_ids" type="string[]">
      Limit results to usage from specific workflows. Pass an array of workflow IDs.
    </ParamField>
    <ParamField body="module_ids" type="string[]">
      Limit results to usage from specific modules. Pass an array of module IDs.
    </ParamField>
    <ParamField body="user_ids" type="string[]">
      Limit results to usage generated by specific users. Pass an array of user IDs.
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="group_by" type="string">
  The dimension to aggregate results by. Must be one of the `GroupByColumn` enum values:

  - `"workflow"` — Group results by workflow.
  - `"module"` — Group results by module.
  - `"user"` — Group results by user.
  - `"date"` — Group results by date.
</ParamField>

<ParamField body="time_period" type="string">
  A named time period to scope the query. Must be one of the `TimePeriod` enum values:

  - `"day"` — The current calendar day.
  - `"week"` — The current calendar week.
  - `"month"` — The current calendar month.

  Use `start_date` and `end_date` instead for a custom range.
</ParamField>

<ParamField body="start_date" type="string">
  The start of a custom date range (inclusive), in `YYYY-MM-DD` format. Use together with `end_date`. Ignored if `time_period` is set.
</ParamField>

<ParamField body="end_date" type="string">
  The end of a custom date range (inclusive), in `YYYY-MM-DD` format. Use together with `start_date`. Ignored if `time_period` is set.
</ParamField>

### Response

Returns a `UsageResponse` — an array of `UsageRow` objects, one per group.

<ResponseField name="grouped_by" type="string">
  The value of the dimension used to group this row. For example, if `group_by` is `"workflow"`, this will be a workflow ID; if `group_by` is `"date"`, this will be an ISO date string.
</ResponseField>

<ResponseField name="credits_used" type="number">
  Total credits consumed by this group within the queried period.
</ResponseField>

<ResponseField name="token_count" type="integer">
  Total number of AI tokens consumed by this group, if applicable.
</ResponseField>

<ResponseField name="row_count" type="integer">
  Total number of data rows processed by this group.
</ResponseField>

<ResponseField name="run_count" type="integer">
  Total number of workflow runs attributed to this group.
</ResponseField>

## Example queries

### Usage by workflow for the current month

```bash
curl -X POST https://backend.scalestack.ai/v2/usage/query \
  -H "Authorization: Bearer <api_key>" \
  -H "Content-Type: application/json" \
  -d '{
    "group_by": "workflow",
    "time_period": "month"
  }'
```

```json
[
  {
    "grouped_by": "wf_abc123",
    "credits_used": 1240.5,
    "token_count": 84200,
    "row_count": 4150,
    "run_count": 12
  },
  {
    "grouped_by": "wf_def456",
    "credits_used": 380.0,
    "token_count": 21000,
    "row_count": 1200,
    "run_count": 4
  }
]
```

### Usage by module over a custom date range

```bash
curl -X POST https://backend.scalestack.ai/v2/usage/query \
  -H "Authorization: Bearer <api_key>" \
  -H "Content-Type: application/json" \
  -d '{
    "group_by": "module",
    "start_date": "2024-04-01",
    "end_date": "2024-04-29"
  }'
```

```json
[
  {
    "grouped_by": "mod_firmographics_01",
    "credits_used": 875.0,
    "token_count": 0,
    "row_count": 3500,
    "run_count": 10
  },
  {
    "grouped_by": "mod_email_verify_01",
    "credits_used": 450.0,
    "token_count": 0,
    "row_count": 4500,
    "run_count": 10
  }
]
```

### Usage by date for a specific workflow

```bash
curl -X POST https://backend.scalestack.ai/v2/usage/query \
  -H "Authorization: Bearer <api_key>" \
  -H "Content-Type: application/json" \
  -d '{
    "filters": {
      "workflow_ids": ["wf_abc123"]
    },
    "group_by": "date",
    "start_date": "2024-04-22",
    "end_date": "2024-04-29"
  }'
```

```json
[
  {
    "grouped_by": "2024-04-22",
    "credits_used": 155.0,
    "token_count": 10400,
    "row_count": 500,
    "run_count": 2
  },
  {
    "grouped_by": "2024-04-29",
    "credits_used": 310.0,
    "token_count": 20800,
    "row_count": 1000,
    "run_count": 3
  }
]
```

<Tip>
  To monitor per-user spend within your organization, set `group_by` to `"user"` and optionally pass a `user_ids` filter to focus on specific team members.
</Tip>
