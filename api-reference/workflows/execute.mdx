---
title: "Execute a workflow run — POST /workflows/{id}/execute"
description: "Trigger a workflow run in full or append mode, poll run status, pause or resume executions, and run live one-off enrichments without persisting results."
---

Executing a workflow starts a processing run against the workflow's configured modules. You can run a workflow in `full` mode to process all input data from scratch, or in `append` mode to process only new rows added since the last run. After triggering an execution, poll the status endpoint to track progress.

## Execute a workflow

```bash
POST https://backend.scalestack.ai/v2/workflows/{workflow_id}/execute
```

### Path parameters

<ParamField path="workflow_id" type="string" required>
  The unique ID of the workflow to execute.
</ParamField>

### Body parameters

<ParamField body="run_mode" type="string">
  Controls how the workflow processes data. Use `"full"` to reprocess all input rows, or `"append"` to process only rows added since the last successful run. Defaults to `"full"`.
</ParamField>

<ParamField body="input_data" type="object">
  Optional inline input data to pass directly into the workflow for this run. If omitted, the workflow uses its configured data source.
</ParamField>

<ParamField body="append" type="boolean">
  When `true`, output rows from this run are appended to existing results rather than replacing them. Defaults to `false`.
</ParamField>

### Example request

```bash
curl -X POST https://backend.scalestack.ai/v2/workflows/wf_abc123/execute \
  -H "Authorization: Bearer <api_key>" \
  -H "Content-Type: application/json" \
  -d '{
    "run_mode": "append",
    "append": true
  }'
```

### Response

Returns a `BaseRunResponse` object.

<ResponseField name="run_id" type="string">
  The unique identifier for this execution run. Use this to poll status.
</ResponseField>

<ResponseField name="status" type="string">
  The initial status of the run. Will be `"pending"` immediately after triggering.
</ResponseField>

<ResponseField name="workflow_id" type="string">
  The ID of the workflow being executed.
</ResponseField>

### Example response

```json
{
  "run_id": "run_xyz789",
  "status": "pending",
  "workflow_id": "wf_abc123"
}
```

## Poll run status

After triggering a run, poll this endpoint to track its progress.

```bash
GET https://backend.scalestack.ai/v2/workflows/{workflow_id}/status
```

### Example request

```bash
curl https://backend.scalestack.ai/v2/workflows/wf_abc123/status \
  -H "Authorization: Bearer <api_key>"
```

### Run status values

| Status | Description |
|--------|-------------|
| `pending` | The run has been queued and is waiting to start. |
| `running` | The workflow is actively processing data. |
| `completed` | The run finished successfully. |
| `failed` | The run encountered an error and stopped. |
| `paused` | The run was manually paused. |
| `cancelled` | The run was cancelled before completion. |

### Example response

```json
{
  "run_id": "run_xyz789",
  "status": "running",
  "workflow_id": "wf_abc123",
  "started_at": "2024-04-29T12:05:00Z",
  "completed_at": null
}
```

## Get run history

Retrieve a paginated list of all past runs for a workflow.

```bash
GET https://backend.scalestack.ai/v2/workflows/{workflow_id}/runs
```

### Example request

```bash
curl https://backend.scalestack.ai/v2/workflows/wf_abc123/runs \
  -H "Authorization: Bearer <api_key>"
```

### Example response

```json
{
  "total": 5,
  "page": 1,
  "limit": 20,
  "results": [
    {
      "id": "run_xyz789",
      "status": "completed",
      "workflow_id": "wf_abc123",
      "created_at": "2024-04-29T12:00:00Z",
      "started_at": "2024-04-29T12:05:00Z",
      "completed_at": "2024-04-29T12:22:00Z",
      "updated_at": "2024-04-29T12:22:00Z"
    }
  ]
}
```

## Pause a run

Pause a workflow run that is currently in the `running` state. The run can be resumed later from where it stopped.

```bash
POST https://backend.scalestack.ai/v2/workflows/{workflow_id}/pause/
```

### Example request

```bash
curl -X POST https://backend.scalestack.ai/v2/workflows/wf_abc123/pause/ \
  -H "Authorization: Bearer <api_key>"
```

---

## Resume a paused run

Resume a workflow run that was previously paused.

```bash
POST https://backend.scalestack.ai/v2/workflows/{workflow_id}/resume/
```

### Example request

```bash
curl -X POST https://backend.scalestack.ai/v2/workflows/wf_abc123/resume/ \
  -H "Authorization: Bearer <api_key>"
```

## Live execution

Live execution runs a workflow immediately without persisting the output to your stored results. This is useful for testing or one-off enrichment tasks.

```bash
POST https://backend.scalestack.ai/v2/workflows/execute/live/
```

### Body parameters

<ParamField body="workflow_id" type="string" required>
  The ID of the workflow to execute in live mode.
</ParamField>

<ParamField body="input_data" type="object">
  The input data to process during the live run.
</ParamField>

### Example request

```bash
curl -X POST https://backend.scalestack.ai/v2/workflows/execute/live/ \
  -H "Authorization: Bearer <api_key>" \
  -H "Content-Type: application/json" \
  -d '{
    "workflow_id": "wf_abc123",
    "input_data": {
      "rows": [
        { "email": "jane@acme.com", "company_name": "Acme Corp" }
      ]
    }
  }'
```

<Note>
  Live execution results are returned directly in the response and are not saved to your workflow's data store. To persist results, use the standard [execute endpoint](#execute-a-workflow) instead.
</Note>
